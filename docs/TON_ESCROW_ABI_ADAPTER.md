# DealEscrow v1 ABI adapter and golden vectors

**Status:** provisional implementation, TON testnet only. This document records the reproducible artifact pins and serializer vectors; it is not an independent contract audit or authorization to submit testnet transactions.

## StateInit layout

The serializer follows the source types in `contracts/ton-escrow-poc/contracts/types.tolk` and the generated Acton TypeScript wrapper:

- `EscrowStorage` has refs to `DealTerms` and `DealProgress`.
- `DealTerms` has refs to `DealRoles`, `DealAsset`, `DealMoney` and `DealSecurity`, followed by signed int32 network ID `-3` and uint16 protocol version `1`.
- `DealSecurity` has refs to three-key oracle and resolver sets.
- `DealProgress` starts at state 0 with zero deadline/dispute/attempt IDs, pending action 0, both flags false, and refs to zeroed evidence and empty recovery cells.
- StateInit TL-B is `split_depth=None, special=None, code=Some(^Cell), data=Some(^Cell), library=empty`.
- The raw address is workchain 0 plus the StateInit representation hash.

## Message encoders

Wallet messages are constructed from the versioned Tolk structs, not from user-provided opcodes or payload strings:

- `ActivateDeal`, `FundDeal`, `AcceptDeal`, `OpenDispute`, `TimeoutDeal`, `RecoverUnexpectedNft` use the generated ABI structs.
- TEP-62 `NftTransfer` uses opcode `0x5fcc3d14`, null custom payload, exactly 0.01 TON forward amount and inline payload `0x56454e46 || dealSalt`.
- All wallet payloads are unsigned TON Connect requests. Server-side signing, wallet custody and submission are not implemented.
- Payout/refund are contract-initiated and deliberately have no user wallet encoder.

`verify_message_vectors.ts` creates fixed message BOCs with the generated Acton wrapper and `@ton/core 0.63.1`. CI uploads their JSON output as part of the `ton-escrow-acton-artifacts` workflow artifact. Backend tests compare encoded body BOC hashes with the cross-generated fixed vector. Regenerate only alongside an ABI/protocol review; do not update expected hashes just to make tests pass.

## Reproduce in CI

From `contracts/ton-escrow-poc`:

```bash
python3 -m unittest discover -s scripts -p 'test_*.py' -v
python3 scripts/verify_frozen_files.py
acton init
acton build
python3 scripts/verify_build_matches_manifest.py
acton wrapper --all
acton wrapper DealEscrow --ts --output wrappers-ts/DealEscrow.gen.ts
npm install --no-save --no-package-lock @ton/core@0.63.1 tsx@4.19.2
npx tsx scripts/verify_state_init_vector.ts
npx tsx scripts/verify_message_vectors.ts
acton fmt --check
acton check
acton test --coverage --no-studio-reporting
```

From `backend` after installing `.[dev]`:

```bash
ruff check app tests migrations scripts
pytest tests/escrow/test_escrow_contracts.py -q
```

The contract CI artifact includes `build/state_init_vector.json`, `build/message_vectors.json`, generated wrappers and the compiled contract artifacts. Keep the artifact alongside the exact workflow run and head SHA when reviewing vector changes.

## Required review boundary

A successful build or matching vector proves serializer consistency against the generated compiler wrapper; it does **not** prove contract safety. The adapter remains provisional until Agent 2's independent TON/Tolk review, Agent 1's provider finality/action persistence integration, complete lifecycle tests, and explicit owner acceptance are complete. No mainnet, real-value funds, server-side signing or production deployment is in scope.
